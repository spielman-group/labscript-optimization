# Documentation findings

Open issues in labscript-optimization's code, documentation and packaging, for decision item by item. Each entry says what is wrong and the smallest fix.

1. **The package is not on PyPI.** `README.md:23-24`, `UPGRADING.md:14-15` and `docs/source/getting-started.rst:13-14` install from a clone of the repository, because PyPI has no project of this name. Fix: Ian may publish the package, after which the three places give `pip install "labscript-optimization[lyse]"`.
2. **The `lyse` extra names no versions.** `pyproject.toml:49-50` lists `lyse` and `runmanager` bare, but the routine needs their Development branches (`README.md:29`), which have `lyse.Routine`, `lyse.data(where=...)`, `save_to_h5` and `submit_shots` with `sequence`, so a plain install may get an upstream release that lacks them. Fix: pin minimum versions once the suite releases them.
3. **An `expr` that uses runmanager's names returns a numpy scalar.** `config.py:205-209` evaluates an `expr` in runmanager's namespace, where `exp` and `sqrt` are numpy's, so `lambda x: exp(x)` gives `np.float64(1.284...)` from `GlobalMapping.evaluate` (`config.py:237-242`). `Config.globals_for` documents plain Python values, because runmanager writes a submitted value's `repr` into the global (`config.py:342-351`), and a numpy scalar's repr is `np.float64(...)`. Fix, for Ian to decide: convert a numpy scalar result to a Python value in `GlobalMapping.evaluate`.
4. **`UPGRADING.md` documents keys this package renamed, not keys M-LOOP had.** `UPGRADING.md:106-107` maps `refit_interval` to `batch_size` and `minimum_observations` to `warmup_observations`, and `UPGRADING.md:108-109` says the last four rows of that table appear only in a file already written for this package. M-LOOP has neither key. `RENAMED_KEYS` (`config.py:87-94`) still refuses both by name, so the page is correct, but it describes this package's earlier names rather than a migration from M-LOOP. Fix, for Ian to decide: keep the rows, or cut them from the page.
5. **The first unknown plot source gets a color close to `main`'s.** `window.py:136` colors a source beyond the four named ones (`window.py:52-57`) with `pg.intColor(len(self.points))`, which is `pg.intColor(4)`, `#00ffaa`, beside `main`'s `#009e73` (`window.py:55`). A learner may name any source (`learners/base.py:112-115`), though none in the package does. Fix: take the new source's color from a list distinct from the four named ones.
6. **`draw_near`, `mutant` and `trial` are public but used only inside their own classes.** `DirectedRandomLearner.draw_near` (`learners/random.py:126`, called at `:143`), `DifferentialEvolutionLearner.mutant` (`learners/differential_evolution.py:165`, called at `:196`) and `trial` (`:185`, called at `:236`) have no other caller in the package, tests, benchmarks, docs or sibling repositories. Fix: give the three a leading underscore, and update the `:meth:` reference to `mutant` at `learners/differential_evolution.py:41`.
