# Documentation findings

Open issues in labscript-optimization's code, documentation and packaging, for decision item by item. Each entry says what is wrong and the smallest fix.

## Code bugs

1. **Reset shows nothing while it waits.** The reset branch (`worker.py:105-110`) builds the interface and calls `check_ready`, which waits up to the 5 s greeting (`runmanager_interface.py:27,75`), and the window is updated only afterwards (`worker.py:147-175`). Until then the old phase, counters and enabled buttons stay on screen and a second click queues a second reset (`window.py:30-34`); "Opening" appears only at the first open (`window.ui:21`), so `window.rst:25` holds only then. Fix: show the Opening phase, with the buttons disabled, before `check_ready` in the reset branch.
2. **A failure after a reply is shown only by the next pass.** An error in `reconcile` or `refill` after the reply (`worker.py:133-135`) stops the session at "Ended: stopped by an error" and queues the exception for the next `hand_over` (`worker.py:136-146`, `82-83`); only the window-command branch prints the traceback (`worker.py:140-142`). If no later pass comes the cause is never shown, and if one does, `run()` raises and lyse pauses analysis and requeues the files (`troubleshooting.rst:12`). Fix: call `traceback.print_exc()` on every branch of the handler.
3. **The window update fails on an unknown source.** `window.py:127` indexes `points[source]`, which holds only start, warmup, main and explore (`window.py:52-61`), while any learner may name its source with any string (`learners/base.py:111-116`), so another string raises KeyError on the GUI thread. No learner in the package does this. Fix: add a point series the first time a source appears.
4. **`config_path` is read relative to the working directory.** `routine.py:201` opens `Path(self.config_path)`, which finds the routine folder only because lyse's worker changes into it before importing the routine; `routine.py:186` and `configuration.rst:16` say "relative to the routine folder". Fix: say "relative to the working directory, which lyse sets to the routine folder", or resolve the path against the folder explicitly.
5. **A dead session thread leaves entries behind.** `Worker.hand_over` appends to `self.unsaved` (`worker.py:73`) before it can raise the dead-thread error (`worker.py:84-88`), and nothing completes that reply, so every later pass adds an entry that is never removed. Fix: raise before queueing when `self.thread` is not alive.
6. **Local `knobs` variables shadow the imported module.** `config.py:430` (module imported at `:49`, used at `:525`) and `learners/__init__.py:93` (imported at `:7`, used at `:83`) each assign a local `knobs` in a function that does not use the module, so nothing breaks today. Fix: rename the two locals.

## Limitations and validation gaps

7. **An `expr` is evaluated in `config.py`'s own namespace.** `config.py:194` calls `eval(self.expr)` with the module's globals, so a lambda can reach `inspect`, `tomllib` and `Parameter`, while a name it likely wants, such as `math` or `np`, loads and raises NameError at the first submission (`config.py:224-227`), mid-session; `configuration.rst:143` documents the second. Fix: pass an explicit globals dict to `eval`, holding `math` and `numpy` if lambdas are meant to use them.
8. **Gaussian process bounds are only shape-checked.** `gaussian_process.py:187-190` accepts any two numbers for `length_scale_bounds` and `noise_level_bounds`: a reversed pair fails inside scikit-learn at the first batch fit, after warmup, and zero or negative bounds pass and make numpy warn inside the fit. `configuration.rst:313` says the load cannot know this. Fix: refuse a pair that is not `0 < low < high` in the constructor, as `trust_range` does (`learners/random.py:101`).
9. **An unselected learner's table has its keys checked but not its values.** `learners/__init__.py:126-142` checks the keys of every named table, but a value is checked only when its learner is built: `[LEARNER.directed_random] trust_gaussian = "false"` loads under `learner = "random"`. `config.py:27-30` says every value in a named table is held to its kind, and `config.py:35-37` says an unbuilt table "goes unread". Fix: reword `config.py:27-37` to say only the keys are checked, as `configuration.rst:313` does, or build every named learner at load.
10. **A group that is not listed is only partly checked.** `config.py:582-619` builds `Parameter` and `GlobalMapping` only for listed groups, so in an unlisted group `min >= max`, an unknown `args` name and an `expr` that does not parse all load, and fail on the day the group is listed. The `check_keys` docstring (`config.py:457-460`) reads as though more is checked, although `configuration.rst` (Groups) says otherwise. Fix: say "keys, required keys and types" in that docstring, or build the entries of every group and keep only the listed groups' mappings.
11. **A missing `[ANALYSIS] groups` gets the wrong refusal.** `config.py:560` defaults `groups` to `[]`, so omitting it ends in "no parameters are enabled. ANALYSIS.groups is []" (`config.py:621-625`), where an omitted `cost_key` says it "is required" (`config.py:645-646`); `configuration.rst` calls `groups` required. Fix: raise "ANALYSIS.groups is required" beside the `cost_key` check.
12. **`directed_random` cannot be asked for the whole space from a file.** Its `trust_region=None` means the whole space (`learners/random.py:63-66`), but TOML has no null and a scalar of 1.0 is refused (`space.py:169`), so its default of 0.05 cannot be removed. Fix: accept a scalar of 1 at `space.py:169`, whose range around any center already covers the space, or document `explore_fraction = 1` as the way.

## Code comments and docstrings that are wrong

13. **`Parameter.enable` says a disabled parameter stays at its start value.** `space.py:28` reads "leaves the parameter out of the search at its start value", but a disabled parameter gets no mapping (`config.py:597-601`), so its runmanager global keeps whatever value it holds, and `ParameterSpace` drops it, start included (`space.py:63`). Fix: say that.
14. **`explore_runs` is described from the previous batch's first point, and counted from its last.** `gaussian_process.py:25-27` and `626-628`, and `UPGRADING.md:298-299`, count explorer shots "from one batch's first point to the next's", but `gaussian_process.py:732-733` counts from the last batch point; the comment at `729-731` says why that is equivalent while a batch goes out unbroken. Fix: write "last point" in those four places.
15. **The `stopped` comment names the wrong shot.** `routine.py:52-57` says the first shot carrying a reason is the shot the run ended on, but `worker.py:81` gives every shot of a pass the same status, so every shot of the pass that stopped the session carries it. Fix: say the first shot carrying a reason is in the pass the run ended on.
16. **The `config.py` module docstring omits keys the code accepts.** `config.py:1-42`, rendered at the top of the API page, leaves out `cost_key` and `maximize` under `[ANALYSIS]` (`ANALYSIS_KEYS`, `:89`), `enable` under `[RUNMANAGER_GLOBALS...]` (`GLOBAL_KEYS`, `:146`), and the `[GENERAL]` keys by name (`GENERAL_KEYS`, `:95`). Fix: add the three, or replace the format description with a pointer to the Configuration page.
17. **The package docstring's example does not run, and the docstring is not on the API page.** `__init__.py:10-12` calls `numpy.random.default_rng()` without importing numpy and uses an undefined `history`, and `api/index.rst` has no `automodule` for the package. Fix: import numpy as `np`, define `history`, and add `.. automodule:: labscript_optimization` to the page.

## API-reference rendering

18. **A colon in the first line of a `#:` comment is read as a type.** `config.py:244-245` ("...runmanager's queue: the hint every learner is handed.") renders `num_buffered_runs` with the type "How many of this session's shots to keep in runmanager's queue" and the description starting at "the hint". Fix: end that sentence with a period.
19. **Two data items render their values.** `routine.py:192` shows `icon` as the absolute path on the build machine, and `learners/__init__.py:34` shows `LEARNERS` as the full repr of a dict of four classes. Fix: add `#: :meta hide-value:` to both comments.
20. **The `OptimizationRoutine` attributes are documented twice.** The Attributes section (`routine.py:183-188`) and the class attributes (`routine.py:191,193`) both describe `config_path` and `interface_factory`, and `api/index.rst:7-11` works around the duplicate warning with `:exclude-members:`. Fix: document the attributes with `#:` comments and drop the Attributes section and the `:exclude-members:` line.
21. **`Bases: Routine` is not a link.** `routine.py:176` subclasses `lyse.Routine`, which the docs build mocks (`conf.py:67`) and lyse's published docs may not document, so nitpicky mode reports it as unresolved. Fix: leave it as plain text, and add it to `nitpick_ignore` if the nitpicky build is to run clean.
22. **Public names with no docstring, and internals shown as public.** Without a docstring on the page are `OptimizationRoutine.run` and `close` (`routine.py:209,218`), `DirectedRandomLearner.draw_near` (`learners/random.py:125`), and `DifferentialEvolutionLearner.mutant` and `trial` (`learners/differential_evolution.py:165,184`); `Config` has a one-line docstring and bare `space`, `globals`, `cost_key`, `maximize`, `learner`, `max_num_runs` and `seed` (`config.py:231-260`). Internals also appear because their names are public: `replay` and `sample_new_member` (`differential_evolution.py:136,158`), `centre` (`random.py:107`), and the instance state `GaussianProcessLearner.computation` and `ready` (`gaussian_process.py:686-689`). Fix: add the missing docstrings, and give the internals a leading underscore.
23. **Public functions describe arguments and returns in prose.** `load` and `loads` (`config.py:538,533`), `extract` and `save_status` (`routine.py:99,139`), and `validate_options` and `build` (`learners/__init__.py:100,145`) have no Parameters, Returns or Raises section, and `load` and `loads` say nothing about the `ValueError` they raise for a bad file. Fix: give each a NumPy-style section for what the page's reader needs.
24. **References to names the page does not list.** The names are `SHOT_RESULTS` (`routine.py:58`, referenced at `:13,140`) and `NO_VALUE_YET` (`:74`, referenced at `:153`); `GlobalMapping` (`config.py:154`, the type of `Config.globals`) and `from_dict` (`:544`); `Observation` (`observations.py:28`, in the signatures of `propose`, `acquire` and every `ask`); `GaussianProcess` (`gaussian_process.py:153`) and its `point_variances` (`:266`, referenced at `:3,594`); `WARMUP_SOURCE`, `BATCH_SOURCE` and `EXPLORE_SOURCE` (`:122-128`, referenced at `:45-47`); `STRATEGIES` (`differential_evolution.py:43`, referenced at `:55,64`). Two more are written short: ``:meth:`propose` `` in `random.py:42` and `differential_evolution.py:214` (it is inherited, so it does not resolve from `ask`) and ``:class:`ParameterSpace` `` in `learners/base.py:155`. Fix: add the names to the `:members:` lists in `api/index.rst`, and write the last two with their full paths.
25. **References and types that cannot resolve.** `sklearn.gaussian_process.GaussianProcessRegressor` (`gaussian_process.py:3-4`) has no intersphinx target, because `conf.py` has no scikit-learn entry; `concurrent.futures._base.Future` is the rendered type of `GaussianProcessLearner.computation` (`gaussian_process.py:687`); and the type words `sequence` (`learners/base.py:100,141`), `optional` (`gaussian_process.py:613,615`), `learner` (`:620`) and `callable` (`routine.py:187`) are read as classes. Fix: add `'sklearn': ('https://scikit-learn.org/stable/', None)` to `intersphinx_mapping`, and write the type words as types (`Sequence[Observation]`, `Callable`) or drop them.

## UPGRADING.md

26. **The config file and routine folder have different names in different places.** `UPGRADING.md:3,32,40` and `issues/lyse_class_routine.md:22,30` call the file `mloop_config.toml`, and `issues/lyse_class_routine.md:20,157` call the folder `optimization_multishot.lyse`, where `configuration.rst:14,21`, `getting-started.rst:41-43`, `routine.py:9`, `__init__.py:21` and `examples/` use `optimization_config.toml` and `optimization.lyse`. `UPGRADING.md` may keep the old name on purpose, as the file the reader already has. Fix: use the example's names in `issues/lyse_class_routine.md`, and decide whether `UPGRADING.md` follows.
27. **The install step differs from the README.** `UPGRADING.md:13-15` installs without the `[lyse]` extra that `README.md:23,30` and `getting-started.rst:13` use, and `UPGRADING.md:28-29` says an older suite "fails at the first pass and says so", where `README.md:35` says it fails with Python's own error and the package checks no versions. Fix: copy the README's command and wording.
28. **The "What stays the same" bullet omits `enable` and spells the key differently.** `UPGRADING.md:268` says `[RUNMANAGER_GLOBALS...]` takes `expr` and `args`, but it also accepts `enable` (`config.py:146`), and `UPGRADING.md:269` writes `ANALYSIS.groups` where the pages write `[ANALYSIS] groups` (`config.py` writes the dotted form in its messages). Fix: add `enable` to the list, and write `[ANALYSIS] groups`.
29. **The default `trust_range` band is called middling.** `UPGRADING.md:334,349,361-362` call the band `[0.1, 0.25]` "middling", but it is measured from the worst cost, so it sits at the poor end, as `learners/random.py:57` and `learners.rst:45` say. Fix: say "poor" or "mediocre".
30. **Some prose narrates this package's earlier behavior.** `UPGRADING.md:48-49` ("earlier labscript-optimization versions"), `145-147` ("It used to be dropped instead") and `354-360` (the trust region "now works", with the cause of the old behavior) describe earlier versions rather than the current design, and `UPGRADING.md:382` ends with "The name has to be true." Fix: cut those passages and the sentence.
31. **The fork and branch are named without a link.** `UPGRADING.md:307-319` refers to "the lab's fork of analysislib-mloop" and "the `no_delay` branch's `mloop_controller.py`" with no address. Fix: link the fork and branch, or name them in words a reader can find.
32. **The last three sections restate other pages.** `UPGRADING.md:387-439` repeats what `results.rst`, `window.rst` and `troubleshooting.rst` carry, and `migrating.rst` includes all of it, so the hosted docs say it twice. Fix: cut those sections from `UPGRADING.md`.
33. **The Migrating page has two titles.** `migrating.rst:1` is "Migrating from M-LOOP", and the included `UPGRADING.md:1` adds "Upgrading from M-LOOP and analysislib-mloop" directly below it. Fix: drop the `migrating.rst` title and paragraph, or the first line of `UPGRADING.md`.

## Packaging, installation and docs build

34. **The README tells readers to install a package that is not on PyPI.** `README.md:23` runs `pip install "labscript-optimization[lyse]"`, and PyPI has no such project (HTTP 404). Fix: publish the package, or give the repository install as the only command.
35. **The README's relative links do not resolve on PyPI.** `README.md:7` (`UPGRADING.md`), `:40` (`docs/source`) and `:55` (`LICENSE`) are repository paths, and `pyproject.toml:36-38` makes the README the long description. Fix: write them as absolute repository URLs.
36. **The `lyse` extra does not name versions.** `pyproject.toml:47-53` lists `lyse` and `runmanager` bare, but only their Development branches have `lyse.Routine`, `lyse.data(where=...)`, `save_to_h5` and `submit_shots` with `sequence`, so a plain install gets an upstream release that lacks them. Fix: pin minimum versions once the suite releases them, or say so in the install text.
37. **`benchmarks/README.md` is named in the hosted docs, which do not contain it.** `UPGRADING.md:247`, `learners.rst:56` and `learners/differential_evolution.py:60` give it as plain text. Fix: link it as an absolute repository URL.
38. **The docs have no favicon, and the logo is 256 px.** `docs/source/conf.py:44-45` sets `html_logo` to the 256 px `optimizer.svg` and no `html_favicon`, where lyse and runviewer set a 64 px logo and a `.ico`. Fix: add a 64 px SVG and an `.ico`, and point `conf.py` at them.

Fix: one American-spelling pass over those files.
40. **British spellings remain in identifiers.** `centre` is a parameter of `ParameterSpace.uniform` and `bounds_near` (`space.py:144,197`) and a method of `DirectedRandomLearner` (`learners/random.py:107`), `minimise_acquisition` is a method of `GaussianProcess` (`gaussian_process.py:465,567`), and `analysed` is a function in `routine.py:83,215`; tests call all three. Fix: rename them to `center`, `minimize_acquisition` and `analyzed`, and update the callers in the package and tests with no alias.
